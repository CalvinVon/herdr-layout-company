# Column sidebar

Used by the personal Office and agent-columns layouts.

- The Spaces title and chevron cycle through three steps: fold the current projection to directories / Team Owners / Tabs, fold all Spaces, then expand every Space and all descendants. Hover describes the next action. Switching projections restarts the cycle at its logical group level. Individual group chevrons remain usable. Agents retains whole-block folding and restores its previous size on expansion. Project chevrons show and toggle each folded state.
- The Spaces title, collapse/new controls and `目录 / Team / 默认` switch stay fixed above the independently scrolling Space list, in both the docked sidebar and hover drawer. Both layouts reserve a 72px Spaces minimum so the controls remain visible; Agents keeps its 40px minimum.
- Each displayed group is one native Space. Its project is bound to the machine and canonical repository root; non-Git directories use their physical absolute path. Git worktrees share that project. Changing a terminal's current directory does not change its Space, project label or remembered worktree. Existing duplicate Spaces keep their tabs and panes; metadata identifies their primary container without migrating sessions.
- The `目录 / Team / 默认` control shows three projections of the same pane set without changing Space/tab/pane/terminal identity, order or focus. `目录` flattens a Space's bound working directories into sibling groups that each show only their own agents — no ancestor nesting, no empty parent directories, and one tab's agents land in their own directories. `Team` keeps the real parent-child tree from `terminal.parent` across tabs and directories (unrelated agents stay standalone). `默认` keeps native tab then pane order and never re-sorts or splits by parent-child. The focused agent's own directory/team/tab block gets a weak wash; the focused row keeps a full-width highlight with no border, left block or ring. Directory groups fold independently and, when collapsed, still show branch, session count and a running-state dot; a folded group that hides a running agent plays the aggregate sweep, which stops on expansion.
- Switching into `Team` through the view control or native command folds each team's members beneath its root Owner (PM) session. Standalone sessions stay visible; owners can be expanded manually while remaining in Team. Switching away and back restores the owner-only default without changing directory/tab fold states.
- Tab navigation, pane navigation and contextual menus target the original core space, tab and pane. Mod-only tabs remain visible in all three projections and open their original tab directly, without empty disclosure controls or duplicate mixed-tab sessions. Split groups have a disclosure arrow, layers icon and pane count even when folded. Expanded groups show each visible session's own time and completion state. Folded directory/tab groups summarize hidden activity; a folded Team owner retains its own state and timestamp while showing a sweep for working descendants.
- Switching to another Agent from the Spaces or Agents sidebar first restores any zoomed pane in the current tab; selecting the same Agent leaves it zoomed. Double-click an Agent with a pane to maximize it.
- Session rows size Agent IDs and worktree icons to their content; ordinary terminals do not reserve an Agent ID slot. Only linked (non-primary) Git worktrees show the Worktree directory badge and session/terminal worktree icon, including detached HEAD and worktree subdirectories. Each repository in a multi-folder Space is compared with its own main checkout; a feature branch alone does not make it a worktree. Hovering the icon, directory branch or Worktree badge reveals the worktree name, branch (or detached HEAD) and full root path. On row hover, the status gives way to a drag handle that blends into the row and, where available, a close control.
- Primary Git checkouts retain their directory and branch names without an extra `主目录` badge.
- Session rows show the latest available native status-change time, distinct from the blue working-duration counter; it is hidden while the session is working. Titles and secondary text fade after 48 hours. Today is labeled `今天`. Missing timestamps show `—` and do not trigger fading; this is not a message-update timestamp. Dates use local time and refresh at least once a minute.
- Spaces use a quiet list with a subtle active background; focused and completed session rows retain their own highlights. Project names use the heaviest foreground text when a contained session is working or entered Done/Idle within the last 24 hours; other names use the dim theme color. When an agent's status time is unavailable, recent tab activity supplies the timestamp. Working sweeps use the Space color; a folded Space displays a sweep when any contained session is working. Selecting a different window expands its Space.
- The project coordinator publishes `workspace.tab-labels` through its one-second refresh; Office's personal `project-tabs` bar consumes the same titles and aggregate states. Session rows show the program icon, main/child Agent icon and Herdr terminal ID; the relation follows Herdr's recorded terminal parent. Automatic names follow the lead agent's live title, explicit names remain unchanged. Session icons stay still; a bouncing blue dot for Working and a fixed green dot for Done appear at the icon's lower right in the sidebar and pane headers. Mixed split groups use the layers icon. Long top-bar titles expose the full name in a tooltip.
- Click a displayed Herdr terminal ID in the tab bar or pane header to copy its full address; sidebar IDs stay passive so row clicks keep switching sessions.
- Session pane headers show the blue Herdr terminal ID after the Agent role icon and before the live session title; long titles expose their full text on hover. Double-click the header to toggle pane zoom.
- Clicking a Space header, avatar, title or chevron opens its home when it has no other tabs; otherwise it folds or expands its sessions. The folder count is always visible and opens folder management. The low-contrast drag handle stays visible at the right of the header, brightens on hover or keyboard focus, and supports Up/Down reordering within a machine.
- Project groups follow Herdr's saved Space order. Drag the handle to reorder within a machine; the insertion line marks the upper or lower half of the target card, including expanded cards. Releasing outside the sidebar cancels the drag. Default tabs and panes retain native order across status and timestamp updates; the Idle agent list sorts by descending native activity timestamps.
- Mounted row hover invalidates only its own action/time view; Space hover invalidates only that Space header. Static row caches use row-local visual data, so another session's hover or fallback-status freshness does not rebuild unrelated titles/icons. The docked Agents instance owns fallback polling; drawer copies reuse its shared results, and hidden/collapsed/inactive Agents displays stop duration redraws.
- Bindings persist in `project-bindings.json` under the Herdr app home. Git metadata refreshes at most once per repository every 5 seconds, including every folder in a Space; unavailable machines keep their last known metadata. The project coordinator publishes `workspace.office-groups` in Space order, which Office preserves in its overview.
- In Office layout, the selected office highlights its matching Space; hovering an office highlights the corresponding Space without changing the active Space. Tab rows use backgrounds instead of nested selection borders.
- Agent cards and pane headers show root and worker icons. Sidebar child-session tooltips identify the recorded parent. A split group whose agents share one parent uses that parent as its header even when ordinary terminal panes are present; unrelated agents remain Tab groups. The relation follows Herdr's terminal parent field.
- Claude Code running in a local macOS Herdr terminal reports lifecycle states through `~/.claude/hooks/herdr-core-state.py`; newly started sessions load the hook from Claude settings. Background subagents are not tracked separately by this hook.
- Native commands: `herdr-app do agent-columns-spaces.toggle-block` advances the same three-step Spaces cycle; `agent-columns-spaces.view.directory` / `view.team` / `view.default` switch the projection, and `view.fold` folds or unfolds every group; `herdr-app do agent-columns.toggle-block` toggles the Agents block.
- In Office, Cmd+B and the sidebar button hide the sidebar completely; Cmd+B restores it.
- Both layouts use the same toolbar and right panel for Files (including previews), Editor and Changes. The Changes panel contains History / Changes tabs; History uses the personal `git-history` mod, and Changes retains the working-tree view and Commit action. The panel follows the focused terminal's repository/worktree. The sidebar Magpie button shows or hides the same live routing panel in both layouts. The agent-columns layout omits the Office scene.
- Project creation uses a shared request queue. Opening an existing project selects its primary Space; choosing an agent there starts the requested command. Worktree sessions create Tabs in that Space; splits retain their original Tab and project. The directory `+` launcher keeps its supplied working subdirectory selectable and uses that exact path; project-membership validation still applies before launch. Personal `project-tabs`, `project-pane` and `project-menu` clones route visible creation controls through `agent-columns-new-menu` and `project-worktree`. Both layouts set `terminal_menu` to `project-menu`. These adapters do not intercept Herdr's global built-in commands.
- Both layouts mount one zero-width `project-coordinator` root block using this mod with `coordinator: true`. It renders no UI and owns binding load/save, readiness and request consumption independently of sidebar visibility. Docked and floating sidebar copies only read the shared bindings. A new coordinator claims ownership and marks readiness pending until validated state is loaded and saved; invalid paths, folder membership, machine identity and target-pane checks remain enforced. Null failures retain the readiness gate with a useful message instead of displaying `null`.

Validation: `node readiness-check.cjs` covers a hidden-sidebar coordinator with the existing calvin/Documents/Downloads schema, split requests, machine scope, null read/write failures and rejected invalid targets; `node self-check.cjs` covers project rules, directory/Team/default projection boundaries, native pane ordering, mod-only tab rendering/navigation, folded Team activity and minimum Spaces geometry. `node ../space-home/scroll-check.cjs` covers the scrollable folder selector and subdirectory launch queue. Run `herdr-app check` for both sidebar mods and space-home, then inspect the live window and exercise the disclosure controls and split launcher with the sidebar hidden.
